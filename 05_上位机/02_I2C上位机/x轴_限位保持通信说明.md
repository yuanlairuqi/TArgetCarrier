# x 轴限位保持通信修复（2026-10-25）

范围仅为 x 轴 ESP32-S3 从机和上位机 x 轴模块；靶车源码及控制模块未修改。原有两条程序线与故障联停策略保留。

## 使用

必须配套更新上位机和 x 轴 ESP 固件。D 盘“启动统一控制台.lnk”将指向新版；原来的 app/TargetCarrier-Unified 保留，新的程序位于 app/TargetCarrier-Unified-LimitFix。请关闭旧版窗口，再从新版入口启动。

触发 GPIO1 或 GPIO2：立即请求 STM32 停止，限位锁存，运动与原队列不自动恢复；BLE 通知、查询与 STOP 握手继续。界面显示“通信在线 · x 轴限位锁定”，不能把限位错误当成非法报文或无线断联。

解除限位：先释放 GPIO1、GPIO2，使两路均保持高电平至少 100 ms；等待 STM32 新鲜且匹配当前命令的停止反馈，再点击“限位复位”。条件不满足时拒绝解除，但保持连接；成功后仍保持停止，需要用户重新启动。仍有任一路为低时不能复位，也没有新增自动反向退限位功能。

## 固件

firmware/x_axis_limit_keep_link 为本次实际编译的 ESP32-S3 固件，bootloader/分区/应用偏移分别为 0x0、0x8000、0x10000，详见 flasher_args.json。

本次配置没有真实 ESP-NOW 配对参数：BLE 功能已编译，**无线 USB→GEEK 链路须保留真实 MAC/密钥等配置重新构建再验收**；不能用未配对构建覆盖正在使用的已配对从机。未更改或猜测任何配对值。本次未烧录、未连接设备、未运行电机。

如使用 BLE，可在确认实际板卡与现有配置匹配后烧录本次固件；烧录前关闭占用串口的软件，断开驱动器 PUL/DIR/ENA 等运动控制线并妥善备份现有固件。串口使用实际 COM 号。这里没有自动执行烧录。

## 修复依据

1. 从机原限位错误码 10 超出上位机原 0～9 范围，造成主动断开；现已按合法限位状态处理，未知错误码仍校验。
2. 原从机限位后拒绝 STOP，现允许新序号 STOP 继续回显并获得 STM32 确认；错误 10 仅允许确认停止，绝不能确认运动。
3. 复位用带标记的 v4 STOP 扩展，始终是 opcode 0，不会将新增运动码透传到旧 STM32。旧固件只把它当成 STOP，限位未清不会伪报复位成功；现有 GEEK 可按原 STOP 通路透传，无须修改 GEEK/靶车。
4. ESP-NOW 将限位锁定与实际通信失效分开；正常 STOP 心跳维护会话，真实超时仍作废会话。BLE 上的业务限位拒绝不会转成导致 PC 断开的 GATT 写错误。

## 验证

151 项上位机测试通过（原 140 项 + 11 项限位恢复测试）；12 个 GPIO 主机测试、3 组限位恢复 C 测试、原有 25 组控制回归通过。ESP-IDF 6.1 / ESP32-S3 固件和 Windows EXE 编译成功。模拟覆盖保持连接、复位拒绝/成功、停止确认、非法状态校验、USB 安全心跳及真实租约超时。

软件模拟不能替代真实 BLE、UART、传感器和停机距离验证。STOP 表示请求/控制器输出反馈，不代表机械瞬间停止；真实断电、复位和射频干扰仍可能导致连接丢失。
