## ESP 与 STM32 连线

接收板为已有 M5Stack Stamp-S3Bat（G1～G11 排针），不是 ESP32-S3-GEEK 总机。STM32 为现有 STM32F103C8T6。

| 信号 | 靶车 ESP 引脚 | 靶车 STM32 引脚 | 说明 |
|---|---|---|---|
| SDA | G4 / GPIO4 | PB11 / I2C2_SDA | 双向开漏 |
| SCL | G5 / GPIO5 | PB10 / I2C2_SCL | ESP 输出时钟 |
| DRDY | G11 / GPIO11 | PB1 | STM32 输出，ESP 输入，高电平有数据；必须连接 |
| GND | GND | GND | 必须共地 |

SDA 和 SCL **分别通过一只 2.2 kΩ 电阻上拉到 3.3 V**，短线起步；如果已有上拉，先确认其电压和并联后的阻值。两根信号不得上拉到 5 V。实际总线电容、上升时间和稳定性仍需硬件测量。

```text
3.3V ── 2.2kΩ ── SDA：ESP G4 ── STM32 PB11
3.3V ── 2.2kΩ ── SCL：ESP G5 ── STM32 PB10
                 DRDY：ESP G11 ── STM32 PB1
                 GND ：ESP GND ── STM32 GND
```

先断电再改线。拆除旧的 STM32 PA9→ESP G2、ESP G1→STM32 PA10 两根 UART 线。G1/G2 不用于新 I2C 链路。ESP G8/G9 的 OLED 原接线保留；STM32 OLED 仍为 PB6=SCL、PB7=SDA。表中 3.3 V 是上拉参考电源；没有要求把两个独立供电板的 3V3 输出直接并联。

参数：ESP 为 I2C 主机（I2C_NUM_1），STM32 为 I2C2 从机，7 位地址 `0x42`，时钟 `400 kHz`，节点号 `2`。每次下行/上行 128 字节，另有 12 字节确认。需要配套的两端 I2C 固件，旧 UART 固件不能混用。

## 电机 CAN 连线保留

| STM32 / 收发器 | 对端 |
|---|---|
| STM32 PB9 / CAN_TX | SN65HVD230 CTX / TXD |
| STM32 PB8 / CAN_RX | SN65HVD230 CRX / RXD |
| SN65HVD230 VCC | 3.3 V |
| SN65HVD230 GND | STM32 GND / 总线参考地 |
| SN65HVD230 CANH | 电机 CANH |
| SN65HVD230 CANL | 电机 CANL |

CAN 仍为 1 Mbps，总线两端各配置 120 Ω 终端。电机动力电源按原规格供电。此次只更换 ESP↔STM32 通信链路，不更换电机 CAN 链路、BLE UUID 或上位机协议。

## 构建与固件

在工程根目录执行；输出目录必须是尚不存在的纯英文路径：

```powershell
python tools/build_wired.py --target target-stm --out C:/Users/y/Documents/Codex/work/target-i2c-stm-new
python tools/build_wired.py --target target-esp --paired --out C:/Users/y/Documents/Codex/work/target-i2c-esp-new
```

`--paired` 读取本工程靶车接收端现有的 `pairing.local.defaults`，不生成或更换配对密钥。密钥配置未放入交付源码包。构建脚本不烧录、不打开串口、不控制电机。

STM32 固件从 `0x08000000` 开始。ESP 使用本次生成的 `flash_args` 和分区表中的实际偏移；不能把 STM32 BIN 与 ESP BIN 混用。交付包保留了 ESP 的引导程序、分区表、应用和对应烧录参数。

改线和烧录后应先保持电机动力断开，验证 I2C ACK、DRDY、状态与参数反馈、双方重启/断线和失能行为。软件测试和编译成功不代表已完成硬件验收，也不能证明此前 BLE 或控制租约超时的根因已经消除。
