# 上位机 5.4 故障恢复（2026-10-26）

启动“启动故障恢复版5.4.lnk”或“启动统一控制台.lnk”。先关闭旧 5.1，再连接 TC-Target。
EXE 与同目录 _internal 必须一起保存。无需为本次上位机更新再次烧录 STM32 / ESP。
本次按要求不额外备份，旧版本应用目录保留。

## 修复

- 修正反馈年龄：收到更新的STM32/电机帧后，旧健康帧的传输年龄不再持续叠加到更新反馈上；各自本地接收年龄与桥接报告的源年龄仍分别校验，过期反馈不会因单独的健康帧刷新而复活。300ms阈值保留。

- 不再每250ms重复写入未变化的增益。增益在连接后、停止恢复或参数改变时、仅在失能期间发送一次；使能期间修改增益须先停止。控制循环扣除GATT写入耗时，不在每次响应后固定再睡50ms。250ms调度保护、STM32的300ms命令超时均保留。
- 新增130ms GATT响应延迟测试，确认不会被重复增益写入拖垮心跳；显示实际GATT往返与控制发送间隔。

- 新增“清除故障（保持失能）”，要求 STM32 / 电机反馈在线、反馈失能、无 ARM、速度绝对值 ≤0.05 rad/s、UART / CAN 正常。
- 旧逻辑把 CLEAR_ERR 与 ESTOP 同帧发送，STM32 在急停分支提前返回，根本不执行清错。现在只发送一次 CLEAR_ERR，ENABLE / ARM 均为0；确认期间持续发送失能指令，保持软件锁定。
- 不能把 BLE 写入或桥接 ACK 作为清错成功。需要清错发送650ms以后的 STM32 和电机反馈均无故障，避开 STM32 的500ms旧故障屏蔽期；然后重新请求急停，仍需手动解除、手动使能。
- 任何停止、切窗、断线都会取消清错，不重放、不自动恢复。持续故障在2.5秒后失败并请求急停。
- 把“等待控制器反馈”替换为实际阻塞原因，区分 STM32 过期、电机过期、控制指令未到 STM32、CAN 恢复、故障锁存及已停止。
- 显示电机原始状态码、安全位、桥接标志、反馈年龄、UART异常及控制丢帧；状态变化写入 connection.log。
- 实际 GATT 写入超时单独报告，不再误称为服务发现失败。

## 操作

1. 搜索并连接 TC-Target，先看实际反馈和提示。
2. 若“清除故障（保持失能）”可用，确认机械环境安全后由用户点击；成功后还要分别点击“解除急停”和“使能靶车”。
3. 若提示“STM32 未收到新鲜控制指令”，清错会禁用：反馈方向已通也不能证明命令方向正常。核对 ESP GPIO1 TX → STM32 PA10 RX、共地、921600 8N1；不要绕过锁定。
4. 若持续自报 ≥8 故障或 CAN 恢复，按提示排查原因，再清错。

STM32 安全位（按位相加）：1授权、2使能、4急停、8故障、16电机反馈过期、32 CAN恢复、64控制链路超时、128授权拒绝。
电机原始状态码：0失能、1使能、≥8故障。上位机“锁存故障=1”可能是 STM32 锁存，不是电机原始错误码1。

## 验证边界

194项软件回归通过，新增清错报文、屏蔽期后持续故障、失能/零速前置条件、停止取消、无自动使能、UART方向提示与超时分类测试。EXE打包成功。
测试不等于实机清错或运动成功；软件不会自动清错、解除急停或使能。实机诊断另见 verification；5.2日志已记录用户手动清错成功，随后使能触发保护，因此5.4继续修复发送调度。
