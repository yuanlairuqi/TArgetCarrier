# 现有流向、带宽预算和建议值

所有数值分为源码配置、理论计算、软件测试、硬件实测四类。本次没有硬件吞吐、时延、无线丢包率或采样精度实测。用户尚未确定通道数、采样率、类型和延迟要求；下列配置均为**建议值**。

## 现有链路（按副本代码复核）

| 流 | 当前格式/方向 | 源码中的约束 |
|---|---|---|
| 控制/调速/停止 | Vue→GU/1 72 B USB→WN/1 80 B无线→UART v2 32 B→STM32 | 有会话/序号、停止握手、租约和应用应答，不能只看MAC回调 |
| 状态/执行反馈 | STM32 UART→从机→无线→GEEK→USB→Vue | 需核对当前revision/token与新鲜度，缓存转发不等于底层在线 |
| 波形 | S3的PUL/DIR硬件输入捕获→20 B片段→无线/USB→Vue | 100 ms采样窗，约每1 s启动一段；原无线波形至少20 ms/槽；并非已实现多通道ADC |
| 原参数 | 旧速度/profile等业务命令，靶车另有增益/参数路径 | 非通用typed-ID注册表；不能把两套旧业务参数互相套用 |

原x轴UART默认115200 8N1，理论字节上限11520 B/s，32 B帧上限360帧/s/方向（未计调度、空闲和其他业务）。GU/1固定72 B、WN/1正文64 B+认证16 B。原波形20 ms限流意味着最多50个无线槽/s，80 B槽的应用无线数据量上限4000 B/s，**不是无线空口容量，也不是实测有效载荷速率**。原USB为USB Serial/JTAG，COM波特率设置不能直接解释为真实USB线速。

当前资料没有足以推导整条链路“现有实测吞吐”的日志，因此只给源码上限和公式，不补造测试数字。靶车HTTP/ESP-NOW/UART/CAN链与x轴GU/WN链有不同协议和安全语义，旧统一上位机继续独立适配，不将其理论上限合并成同一性能数字。

## 预算方法

设C通道、Fs样本/秒/通道、B每批样本数、D每值字节数（本版4）、Fcmd每秒可靠请求数。

```text
原始采样量             Rraw = C × Fs × D               [B/s]
波形载荷/批            P = 12 + 2C + C × B × D         [B]
波形批率               F = Fs / B                    [批/s]
分片数                 N = max(1,ceil(P/96))
有线槽率               Fslot = F × N                  [槽/s]
UART单方向所需线速     Ruart = Fslot ×128 ×10          [bit/s，8N1]
SPI时钟占用（全双工）  Tspi = 128×8 / SPI_Hz           [s/事务]
SPI占用率              Uspi = Ftransaction × Tspi
I²C读槽+应用确认线位   Ri2c_up ≈ Fslot × ((128+1)+(12+1))×9
请求+应答的额外线位    Ri2c_cmd ≈ Fcmd×[(128+1)+(128+1)+(12+1)]×9
无线应用封装量         Rradio = Fslot ×144              [B/s，不是PHY占用]
```

I²C公式包含一次地址字节/事务和ACK位，不包括START/STOP裕量、时钟拉伸及调度。SPI空轮询也占带宽，即使业务数据为0。ESP-NOW另有MAC/PHY帧头、CCMP、重传、竞争和共存，144 B/s的封装量不能除以标称PHY速率就声称可保证时延。

UART上下行通常是全双工，应分别预算；I²C是共享半双工，要把请求、应答、确认和诊断相加。端到端容量取最慢一段及软件限流最小值。估算延迟还要加批次等待（最老样本约(B-1)/Fs）、轮询、队列等待、无线调度、操作系统/GUI刷新，**不只算线上的位时间**。

## 本版建议配置与实际默认

| 项目 | 建议起点/源码默认 | 条件 |
|---|---|---|
| 有线默认 | UART 460800 / 8N1 | 短线、信号质量合格；没有实测保证 |
| SPI起点 | Mode0，1 MHz，128 B，10 ms调度 | 接收端READY握手、DMA、主机独占 |
| I²C起点 | 100 kHz，0x42，10 ms调度 | 短线和合适上拉，避免高带宽连续波形 |
| 软件演示波形（实际默认） | 2通道U32、25样本/s、B=1 | ticks与参数快照，无ADC/电机意义 |
| 队列 | 高/低各8槽（无线RX低4），波形采集8槽 | 满则显式拒绝或丢最老，不扩为无限队列 |
| 波形时效 | 排队100 ms后丢弃 | 不保证整链路100 ms时延 |
| 请求 | 350 ms超时、最多3次重试、空闲心跳500 ms | 超时后应用状态未知，需读回 |
| 接收会话 | 2 s无有效新请求关闭 | 非电机安全租约替代品 |
| GUI | 100 ms刷新、最多2000点 | 不是硬实时显示；接收与绘图解耦 |

演示波形P=24 B，每秒25槽：UART上行3200 B/s，线位32000 bit/s，约6.94% of460800；无线应用封装3600 B/s；I²C上行读+确认约31950 bit/s。再以持续5次参数请求/s估算，请求/应答/确认额外约12195 bit/s，两者约44.1% of100k，仍需加诊断、心跳/竞争与裕量。空闲心跳与主动请求互斥；不得无条件重复相加成实测利用率。

若后续希望4通道F32、200样本/s，可建议B=4：P=84 B、50槽/s（已达到本包无线波形限流），UART/SPI理论预算可行，I²C读+确认约63900 bit/s，叠加请求后裕量偏小，不建议以该配置作为100 kHz I²C的初始目标。I²C可先降至4通道80样本/s、B=4（20槽/s），再实测决定。当前示例main没有自动切到这些建议配置，需项目采集代码实现相应批量发送。

若未来需要8通道×1 kHz×F32，原始量32000 B/s；按现有固定槽/50槽限流不能满足。本次没有通过提高一个波特率就宣称支持该目标；应重做批量布局、无线承载和采集/时间同步预算，再决定是否改协议。

## 接口选择建议

- UART：接入成本最低、易用逻辑分析仪排查、适合作为默认调参和中低速波形后端；需要处理异步流和RX溢出。
- SPI：更适合板间短距离、高采样吞吐；需要更多线、硬件NSS、DMA和READY时序，不能直接替代长线现场总线。
- I²C：适合低速参数与状态、少通道低速波形；共享半双工、上拉/电容与时钟拉伸限制明显，不能当成无限制双向高速流。

目标芯片和性能指标确定后，应先量化允许的最老样本年龄、关键命令截止时间及丢样策略，再通过硬件测试调整；当前建议未视为用户已确认需求。
