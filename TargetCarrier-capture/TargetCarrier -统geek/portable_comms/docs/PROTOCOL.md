# TC/2 协议与业务语义

## 版本与兼容

旧协议按当前源码复核：USB GU/1 固定 72 B、CRC32；无线 WN/1 为 64 B 正文 + 16 B HMAC，包含节点、启动/epoch、会话、序号和旧业务租约；x 轴 UART v2 固定 32 B、CRC16，含 session/token 和命令、状态、心跳、profile。旧波形是 S3 对 PUL/DIR 输入边沿的快照，不是通用多通道 ADC 数据。它们的编码、停止确认和业务不改。

TC/2 使用独立 `TC 02` 魔数和三端新镜像。旧软件不解释新帧；新模块不将旧运动命令自动翻译成通用控制。没有静默降级、自动识别后改变协议或新旧混传。新旧系统的选用由明确入口和匹配固件决定。

## 固定传输槽

所有多字节整数小端。每槽 128 B，剩余数据区域必须填零；CRC 算法为 reflected IEEE CRC32 / polynomial 0xEDB88320、初值和末异或 0xFFFFFFFF。黄金测试 `123456789 → CBF43926`。

| 偏移 | 长度 | 定义 |
|---|---:|---|
| 0 | 2 | ASCII `TC` |
| 2 | 1 | 协议版本 2 |
| 3 | 1 | 消息类型 |
| 4 | 4 | session，非零；PC 使用随机 2..FFFFFFFF，1 保留本地链路诊断 |
| 8 | 4 | 请求/消息序号 |
| 12 | 4 | 发送方单调毫秒时间，32 位回绕；不代表跨设备同步时间 |
| 16 | 2 | 逻辑消息总载荷长度 0..512 |
| 18 | 1 | 分片索引，从 0 起 |
| 19 | 1 | 分片数量，max(1,ceil(总长/96)) |
| 20 | 2 | 本片有效数据长度 0..96 |
| 22 | 6 | 保留，必须为零 |
| 28 | 96 | 载荷，末片剩余填零 |
| 124 | 4 | 对 0..123 字节的 CRC32 |

无线在完整 128 B 槽后附加 16 B 截断 HMAC-SHA256，总 144 B；再使用 ESP-NOW CCMP 加密单播。CRC 检错与 HMAC 认证用途不同。回调只核对来源、目的和长度、记录本地时间、入队；HMAC/CRC 校验在拥有协议的任务中进行。

| 类型 | 编号 | 载荷 |
|---|---:|---|
| HELLO | 1 | 空载荷；建立当前参数会话 |
| READ | 2 | `id:u16` |
| WRITE | 3 | `id:u16,type:u8,reserved=0:u8,value:4B` |
| RESULT | 4 | 见下表；应答使用对应请求的 session 和 seq |
| WAVE | 5 | 波形头、通道表和数据 |
| STATUS | 6 | 链路诊断；可分片的通用状态也可由应用自行发送 |
| CONTROL | 7 | `opcode:u16, application_payload`；默认不支持，可注册应用处理器 |

类型 1=U32、2=I32、3=IEEE754 float32，每个值 4 B。参考注册表：ID 1 U32、范围 1..1000、初值25；ID 2 F32、范围0..100、初值1.0。它们是无电机意义的演示参数，不宣称为已确认的步兵参数定义。

### 参数与业务结果

参数 RESULT 固定 12 B：`request_type:u8, code:u8, id:u16, value_type:u8, reserved:u16, stage:u8, value_or_detail:u32`。HELLO RESULT 为8 B，其byte4=2表示协议版本，stage=0。

`code`：0 OK、1 格式/类型/只读错误、2 越界或非有限浮点数、3 未知ID、4 BUSY（应用可返回）、5 STALE（保留）、6 UNSUPPORTED。参考参数表的每项声明类型、写权限和范围；写入先校验后更新 `bits`，然后应答，不做部分写。

`stage`：0 拒绝或握手；1 参数已在协议所有者上下文更新；2 业务已接受；3 业务已执行。业务处理器返回阶段，通信层不会替业务声称执行成功。参数值在赋值后立即对同一任务可见；控制算法是否在下一周期采用新快照，必须由接入方明确实现。保存 RAM 值不等于硬件动作，也不代表写入 Flash。

送达层级：ESP-NOW MAC回调成功 ≠ 收到完整有效逻辑消息；匹配的 RESULT 是接收应用已处理请求的证据；stage=1 是参数RAM已应用；业务stage=3必须来自真实业务处理器。GUI分别展示USB、接收端无线诊断新鲜度、STM32匹配应答和参数结果，互不替代。

## 会话、去重、超时

- 一个接收服务同时接受一个会话；活动会话中的不同session HELLO被忽略，2 s 无新请求后会话失效。失效后写/控制不执行，必须先HELLO。
- PC一次只允许一个请求在途，命令等待队列8项。空闲时每500 ms读ID1作参考心跳。
- 单请求350 ms无匹配应答时，用**同session、同seq、同载荷**重发；最多3次重试，总计4次尝试。耗尽后状态为“是否应用未知”，清空待发写入、重建随机session，用户应重新读值。
- 接收端采用32位有符号差判断新序号，要求相邻有效序号距离小于2^31。最新已完成请求缓存类型、载荷和应答；完全相同的重复请求只重发缓存，绝不再次调用业务。相同seq而载荷不同的包拒绝；更老序号拒绝。超过缓存范围的旧请求不回放。
- 重连不会重放未执行的GUI队列；断开清空队列。迟到应答必须同时匹配当前session、seq、请求类型，参数结果还必须匹配ID和长度。
- 会话随机值不是密码学挑战，也没有掉电去重日志。业务处理器应继续执行自己的使能/停止/租约检查；本包不会替代原电机保护。本次不实现跨掉电持久的“恰好一次”。

## 分包与恢复

最大消息512 B、每片96 B、最多6片。必须从0开始连续、同session/seq/type/total/count；首片重启组装，缺片/乱序/矛盾长度丢弃当前组装，不拼接猜测。自首片起300 ms超时；接收服务tick负责清理。所有片CRC通过才加入；逻辑消息收齐才进入参数/控制处理。每个服务实例保留一个组装上下文，发送方应串行发送一个逻辑消息的所有片，不在其中插入另一条分片消息。

UART/USB采用滑窗重同步；SPI/I²C失败则丢弃该事务，下一事务恢复128 B边界。协议没有每片重传和无限重试；可靠请求按整条消息重发。`tc_send`在输出回调拒绝时返回false，之前接受的片可能已在队列里，调用者须整条重试，不能假定原子提交。波形只用单槽、不重传。

各传输队列有界且按本地入队时间丢弃超过100 ms的待发/待收槽。无线单包在途；250 ms仍无MAC回调时关闭本包无线发送，防止无标识的迟到回调归到下一包；本参考实现需重启/重新初始化后恢复，不自动切换链路。其他发送错误会计数并退出本次提交，可靠性由整消息重试实现。静态SPI/I²C已发布的一个邮箱可等待主机读取；迟到RESULT仍受主机请求匹配限制，不能当作当前状态。

## 波形

载荷：`format=1:u8, channels:u8, samples:u8, type:u8, first_sample_us:u32, period_us:u32, channel_ids:u16[channels], values[ samples ][ channels ]`。所有通道本消息同类型；需要混合类型时发不同消息。通道ID由项目定义，不借用GUI内部对象。

最大单槽96 B：`12+2C+4CB ≤ 96`。时间来自采样方单调计数器；首样本+采样间隔描述批次时序，不以发送/接收时刻充当采样时刻。32位微秒约71.6分钟回绕；显示/记录应按无符号差扩展。本包不提供跨板时钟同步或ADC触发驱动。

`tc_wave_buffer_emit`把已采集快照拷贝进8槽环形缓冲，满时丢最老；发送flush有最小间隔，下游拒绝时保留当前槽，100 ms后丢弃。高优先级命令/应答先发、波形低优先级，无无限积压。无线额外限制波形至少20 ms/槽，即最多50槽/s。采样高于可发送速率时应批量打包或在采样侧配置降采样；本版自动策略是丢最老，不会偷偷改变用户采样率。

参考main每40 ms采集一次软件 `ticks` 和演示参数值，2通道U32、每批1样本；这既不是ADC，也不是电机实测波形。
