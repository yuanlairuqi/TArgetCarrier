# GPIO1 / GPIO2 任一路低电平限位停止

此修改针对本目录 ESP32-S3 无线从机。实际 PUL/DIR 由 STM32 产生，GPIO6/7 是输入采集；本轮配套修改了上位机的 x 轴限位通信和复位模块；STM32、GEEK 主机和靶车不修改。

## 接线

| 接点 | 连接 |
| --- | --- |
| 传感器1黑线 BK | GPIO1 |
| 传感器2黑线 BK | GPIO2 |
| 每只传感器棕线 BN | 直流 +5V（按照片铭牌 5～30V，本方案使用5V） |
| 每只传感器蓝线 BU | 电源0V，与 ESP32-S3 GND 共地 |
| GPIO1 → 10kΩ → 3.3V | 独立上拉 |
| GPIO2 → 10kΩ → 3.3V | 独立上拉 |

先断开 GPIO，用上拉和万用表确认每路输出兼容3.3V：未触发约3.3V，触发为有效低电平；本品牌输出内部电路尚无官方资料确认。禁止将GPIO上拉到5/12/24V。若只安装一路，另一路仍保留10kΩ上拉。NPN常开接法不能检测断线：断线通常显示未触发。

## 行为

GPIO1 或 GPIO2 任一路下降沿触发，ISR 在内部临界区锁存并通知优先级12任务。任务通过原桥接协议发送 opcode 0 立即停止，覆盖待确认运动和排队换向，保留原串口ACK/重试逻辑。opcode 3 是减速停止，本功能不使用它。

命令入口、控制循环和发送前也检查锁存/电平；停止任务有5ms换算为RTOS tick的后备轮询。这不是5ms停机上限。ISR不打印、不调用UART、不删除控制任务。UART发送与控制状态共用互斥锁，避免STOP之后再发出先前准备的运动帧。

开机已有任一路低电平，或输入初始化失败，也禁止运动。错误码10为限位锁存，GPIO释放、BLE重连、无线重连、普通STOP及新运动指令都不会清除。解除方式：两个传感器都释放并保持高电平至少100ms，等待新鲜、匹配当前命令的STM32停止反馈后，在新版上位机点击“限位复位”。无需重启ESP或断开BLE。条件不满足则继续锁存并保持通信；复位后仍需手动重新启动，不自动恢复原运动。普通STOP现在会更新命令序号、协议及停止回显，但绝不解除锁存。

这是ESP检测→UART→STM32停止PUL的控制停机；不是硬件直接切断。已排入UART发送缓冲的数据、UART故障、任务调度及STM32处理均影响响应时间；机械惯性仍会造成滑行。ENA和DIR不在本修改中直接操作。若需要硬件限位，应在真正产生PUL的STM32或驱动器停机输入上设计。

## 2026-10-25 限位保持通信修复

上位机将错误码10作为有效业务状态，不再主动断开BLE。BLE限位拒绝不返回导致PC断链的GATT写错误；ESP-NOW限位不再直接撤销会话，正常STOP心跳仍维护租约，实际无通信超时仍会作废会话。新版PC和本次从机固件必须配套更新。151项PC测试、12个GPIO用例、3组限位恢复C测试和25组原控制回归通过。固件编译通过，尚未烧录或实测。新产物见上一级verification/limit_link_20261025或交付目录firmware/x_axis_limit_keep_link。
