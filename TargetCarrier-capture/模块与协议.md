# 模块、协议、接线与移植

## 结构与任务所有权

- `独立原型/recorder_core`：原独立原型按字节保留，包含 CB 批量格式及离线 CR 原型工具。
- `recorder_core/capture.c/.h`：CR/1 记录，40 字节，U32/I32/F32、样本/状态/事件、来源、通道、单位、boot、seq、微秒时间和 CRC。
- `fragment.c/.h`：20 字节低优先级分片，8 字节片头 + 12 字节数据，500 ms 重组期限。
- `source.c/.h`：接收端单任务采集队列（32 条）、节流发送、400 ms 片组期限、超过 1 秒未发样本丢弃。每 40 ms 最多入无线队列一片。断线清空，不为控制恢复缓存命令。
- `sd_geek.c/.h`：GEEK 板载 TF SPI3 挂载；不与 LCD 的 SPI2 复用。挂载失败不格式化。
- `wave_store.c/.h`：仅 GEEK 低优先级 `wave_sd` 任务访问文件系统；64 帧录制输入、4 个命令、8 个应答队列。主循环只做非阻塞投递/取回。
- 每套工程 `main/capture_core` 有上述模块的自包含构建副本，ASCII 构建快照无须回读桌面原工程。GEEK 实际编译存储适配，接收端编译 capture/fragment/source。
- `serial_hub.py`：唯一 COM 所有者，原节点队列保持原行为；观察者订阅可接收 kind 4/7，容量有界、满即丢弃计数，不等待消费者。
- `wave_client.py`：观察线程解析实时记录/状态，独立文件任务发起存储管理请求；与 UI/控制线程分离。断开后状态未知，RPC 超时不重发。
- `wave_history.py`：原始 TCWL 校验、重组、筛选和 CSV；没有任何运动执行路径。
- Vue 页和 `UnifiedBridge.record_*`：录制、目录、备注、删除、下载与本地回放 API。原 x/target 控制适配器保留各自版本。

## 数据量与默认预算

本次选择保守的 **2 Hz 快照**，不是把原 CB/8 批量原型直接套进既有协议。每个 CR 记录 40 B，分成 4 个无线片，每个 WN 正文64B+认证16B。每设备两通道时为 4 条/s、16 片/s、约 1280 B/s 的无线应用载荷（不含 Wi-Fi/加密/重传开销）。原每设备波形限流约 50 片/s，通用源自身再限制 25 片/s；与原 GPIO 波形共用低优先级队列，实际能发多少取决于控制抢占和 RF。

状态/事件变化另占容量。通用队列拥塞会掉样并报告；seq 缺口和通道65535用于诊断，不能承诺无损采集。两节点合计波形最多约100片/s，再加约10状态帧/s，SD 每帧80B，上界预算约 8.8 kB/s、760 MB/天，未计文件系统开销；这是计算上界，不是实测吞吐。

若要求每通道25 Hz甚至更高，应重新做 CB 批次/通道元数据/无线槽预算并验证，不能只把500改成40。手动连续已实现；低频长记录可调快照周期但仍保存状态/原波形；故障触发及触发前环形缓存尚未实现，不应声称存在。接收端无线断线期间的本地存储也未实现。

## 可移植采集入口

```c
cap_source source;
cap_source_init(&source, node_id, esp_boot_id);
// 在单一采集/通信所有者任务中，取得真实的新数据后调用。
cap_source_feed(&source, CAP_SAMPLE, channel, CAP_U32, unit,
                actual_monotonic_us, value_bits);
cap_source_feed(&source, CAP_EVENT, event_channel, CAP_U32, 0,
                actual_monotonic_us, fault_code);
cap_source_poll(&source, authenticated_session_active,
                actual_monotonic_us, send_low_priority_fragment, context);
```

不要从多个任务或 ISR 直接并发调用此无锁模块。传感器任务/ISR 可先送入自己的有界队列，由上述所有者零等待接收，再 feed。I32/F32 用 memcpy 取得32位位模式，避免类型别名。为每个物理量分配固定通道及单位码，并在上位机配置映射。当前单位码0=无量纲/位域，1=Hz，2=mV，3=度；新增单位要一起更新显示映射。

后端适配点已经接入三套工程的原 STM32 接收解析结果：x 轴 `bridge_receive/control_feedback`，靶车 `proto_decode_status`。它们保留原串口/SPI/I²C 所有者，未额外读取同一接口，也未改动 STM32 控制报文。移植其他主控时，在所选后端验证帧与 CRC 后调用 feed；没有假定其他主控已实现新协议。仅当主控主动提供独立采样时间/boot时，才可升级协议描述那一时钟域；不能把 ESP 收到反馈的时间伪称为 STM32 测量时间。

## 无线与 USB

WN/1 原64字节正文、外层认证保持原样；kind4 波形的 byte32 是子类型：1为原GPIO，3为通用CR片。byte4 node、8 ESP boot、12 epoch、16 session；40..59为20字节片，60..63原CRC32。片内为 version/index/count/length 各1B、batch_id U32、12B数据。重组按 node/boot/epoch/session分离；缺片、乱序、超时、CRC及来源不匹配拒绝。通用记录序号每ESP启动递增，允许32位回绕。

GEEK 在原无线认证、帧CRC和原会话过滤之后才投递存储和USB；状态/STOP与控制队列优先于原波形和通用片。采集不会发送新的运动控制类型，也不续期控制租约。原脉冲解码器忽略子类型3，避免破坏现有GPIO重组。

USB GU/1仍是72B，正文64B，外层CRC32。保留原kind1控制、2状态、4波形、5诊断；新增kind6存储请求、7存储应答。存储管理命令由GEEK本地处理，不向无线控制器转发。

请求正文：`RC`, version1, op(U8), nonce(U32), record_id(U32), offset/cursor(U32), length(U8), reserved3B, data[44]。应答：`RS`, version1, op, nonce, error(U8), flags(U8), length(U8), reserved(U8), offset(U32), record_id(U32), data[44]。全部整数小端。flags bit0已挂载、bit1录制中。

| op | 功能 | 说明 |
|---|---|---|
| 1 | 状态 | 自动报告nonce0；载荷含SD丢帧/当前段字节数/录制UTC/错误 |
| 2 | 开始 | data前8B是电脑UTC毫秒；新建文件，不覆盖旧记录 |
| 3 | 停止 | 有界排空、同步、关闭后应答 |
| 4 | 目录 | cursor为上一个ID，返回下一个更大ID；空载荷为结束 |
| 5 | 原始读取 | id+字节偏移，最多44B；空载荷为EOF |
| 6 | 写备注 | UTF-8最多44B |
| 7 | 删除 | 停止录制时才允许 |
| 8 | 挂载 | 手动重试，录制时拒绝 |
| 9 | 读备注 | 使用相同id/offset |

error：1未挂载，2I/O，3忙，4格式，5不存在，6卡余量不足，7编号空间耗尽，8重复nonce内容不一致。GEEK仅缓存最近8个请求的应答以抑制常见重复；客户端本身不自动重试写操作。命令队列或USB拥塞可能没有应答；超时表示结果未知，随后查询，不推断成功或失败。

## 原始文件 TCWL/1

文件头32B：magic `TCWL 01 00 00 00`、电脑UTC毫秒U64、记录ID U32、GEEK起始单调微秒U64、CRC32 U32。每帧80B：GEEK接收微秒U64、WN正文64B、SD输入队列累计丢帧U32、CRC32 U32。CRC为IEEE CRC32（与zlib相同），涵盖各结构除最后CRC以外的字节。

单文件在64MiB前自动另开一段，跨段UTC由同一录制时钟估算。只保存上行波形/状态，不保存或回放可执行的下行命令。备注为同ID `.note`。原始片和状态一直保留；CSV解码通用样本，原GPIO/状态以raw_hex行保留，未将GPIO边沿误标成真实编码器位置。

## 接线与资源

GEEK 使用板载microSD，无新增外接线。V1.1官方参考原理图：[Waveshare ESP32-S3-GEEK V1.1](https://files.waveshare.com/wiki/ESP32-S3-GEEK/ESP32-S3-GEEK-Schematic1.pdf)。当前适配 SCK36、MOSI35、MISO37、CS34，SPI3、10MHz；LCD保留SPI2/GPIO7～12。必须在实物上核对版本；GEEK与Stamp-S3Bat是不同板。

ESP-IDF 6.1当前本地 `ffconf.h` 中 `FF_FS_EXFAT=0`，并参照[官方FatFs说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/storage/fatfs.html)。当前构建要求受支持的FAT卡格式；64GB卡实际格式、容量寻址和稳定性未实测；无自动格式化逻辑。

接收端保持基线选定后端，每次只启用一个。SPI当前配置是G3 SCK、G4 MOSI、G5 MISO、G11 CS，STM32对应PA5/PA7/PA6/PA4，四线无READY；G10继续保留用户输出。I²C当前G4 SDA、G5 SCL、G11 READY，地址0x42、400kHz；STM引脚以其原工程板级实现为准，勿照SPI接线。I²C头文件中的未选中SPI CS=10不会启用。

UART x轴引脚和波特率读取该工程 sdkconfig.defaults/Kconfig，靶车 UART 基线 TX1/RX2、921600。本次没有重分配任何接收端GPIO；UART靶车与Stamp限位脚的物理冲突必须按其实际板卡/既有工程核对，不能把SPI副本的限位说明套到UART副本。已有OLED、脉冲采集、限位输入及G10功能保持原配置。新增传感器前先做资源表，不能凭示例直接接线。
