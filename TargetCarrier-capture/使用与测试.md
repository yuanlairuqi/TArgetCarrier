# 抓波接入：使用与测试

更新：2026-10-29。本次接续“检查并修复靶车通信控制”聊天的录波接入工作。基线是桌面“TargetCarrier -统geek - 抓波”内的 UART、SPI、I²C 三套工程。独立原型保存在本交付的 `独立原型/recorder_core`，原聊天的原型文件未修改。

## 先看交付范围

已接入：ESP 接收端已有 STM32 反馈和可选本地电池 ADC → 通用记录/低优先级无线分片 → GEEK 认证与原会话检查 → 实时 USB 观察，以及 GEEK 独立 SD 任务 → 上位机开始/停止、目录、下载、备注、删除、文件回放与 CSV。

每套上位机有独立的 `上位机/TargetCarrier-Unified/启动抓波控制台.cmd` 和 `app-capture/TargetCarrier-Capture/TargetCarrier-Capture.exe`。原有应用和快捷方式保留；旧 EXE 不会因源码更新而自动获得录波页。必须使用新入口。抓波支持 GEEK USB 链路；BLE 原控制路径保持原样，新增通用记录未通过 BLE 发送。

本次未修改 STM32 控制源码、未烧录、未配对、未操作电机。构建的 ESP 二进制是**未配对版本**，不能直接替代用户设备上的已配对固件。需要实际 MAC、信道、PMK/LMK/认证配置重新成套构建，不能混用三种后端的从机固件。

**已有版本限制：**UART 副本的 `target_wire.py` 要求参数 254 返回 `0x00060100`，但本次基线的靶车 STM32 源码没有相应实现。使能仍可能被拦截。没有取消保护检查、冒充能力版本或移植另一套运动/限位实现。因此，本交付是录波软件接入，不构成整套运动系统可用或安全的结论。SPI/I²C 的上位机基线与 UART 有差异，分别打包，未强行统一控制版本。

## 启动与实时查看

1. 运行所选后端目录中的“启动抓波控制台.cmd”。打开“实时数据与录波”页。
2. 按原流程在设备页连接 GEEK USB，让节点完成已有 STOP/会话确认。录波页复用已建立的串口所有者，不额外打开 COM；只开 BLE 时不会出现通用录波数据。
3. 只有一个已连接 GEEK 时自动订阅；多个串口时在录波页选择。没有有效采样时曲线空白，不生成模拟值。
4. 通道选择格式为“设备:通道”。默认建议快照周期为 500 ms（2 Hz），由 `CAP_SNAPSHOT_PERIOD_MS` 配置，不是已确认的最终采样需求。

| 设备/通道 | 含义 | 类型/单位 | 有效条件 |
|---|---|---|---|
| 1 / 1 | STM32 当前输出频率快照 | U32 / Hz | STM32 反馈在线；不是电机编码器转速 |
| 1 / 2 | ESP 接收端本地电池 ADC 电压 | U32 / mV | 原工程已启用且 ADC 校验有效；未启用时没有此通道 |
| 1 / 100 | STM/ESP/链路错误码组合 | EVENT / 位域 | 快照检查到变化；原高优先级状态帧另行保存 |
| 2 / 1 | STM32 状态中的 yaw | F32 / 度 | 接受新状态时抽取，接收端限频 |
| 2 / 100 | STM32 状态与错误码 | EVENT / 位域 | 新反馈发生变化 |
| 两节点 / 65535 | 源端队列/过期/断线丢弃累计数 | STATE / 次 | 计数变化后尽力发送 |

采样时间是 ESP 接收端观察/接收数据时的单调微秒，不是 STM32 内部采样时刻，也不是全网同步时钟。boot 标识属于 ESP。实时图横轴使用电脑接收时间；表格和原始文件保留 ESP 时间。新的传感器型号、引脚、采样率未假定；增加传感器按《模块与协议》接入。

## 录制与历史

- SD 使用 GEEK 板载槽。无卡时允许实时查看和原控制，录制请求返回未挂载；程序从不自动格式化。
- 点击“查询状态/重新挂载卡”，看到 SD 已挂载后点击“开始录波”。只有 GEEK 应答才表示开始已确认。
- 文件位于卡上 `tcwave/*.twl`，保存认证后的原始状态、GPIO 波形片和通用采样分片，以及 GEEK 接收时间、SD 队列丢帧计数和 CRC。每段约 64 MiB 自动新建文件，直到手动停止、卡剩余不足 1 MiB 或存储错误。分段期间保留队列与丢帧计数。
- 点击“停止录波”后等待应答。任务先停止接收新录波帧，排空有界队列，再 flush/fsync/关闭文件。目录和下载等操作在录制停止时使用。
- “刷新 SD 目录”读取按 ID 排序的记录（一次最多 1000 条）；可保存最多 44 字节 UTF-8 备注，或确认后删除文件。删除不会操作控制器。ID 是该卡当前记录的标识，勿把跨卡/删除后新建的同号文件当成同一条记录。
- 下载时先保存 `.partial`，完成后验证文件 CRC 再改成 `.twl`。超时或断开保留未完成文件，不自动重放操作。USB 小包历史传输只有约数 KiB/s 的量级，速度未实测；大文件建议停止录制、断电取卡后复制原始文件。
- “打开原始文件回放”选择下载的 `.twl` 或直接复制出的文件；可按设备、开始和结束日期时间筛选。图表/表格只保留最后 2000 条供浏览；顺序回放为逐条浏览，不是电机动作重放。CSV 按所选范围流式导出全部有效记录，原文件保留。
- 日期由电脑发起录制的 UTC 时间，加 GEEK 接收单调时间差估算；没有 RTC/时钟同步保证，不可用于跨设备精确相位分析。
- “恢复有效文件前缀”只读取损坏/截断前完整、CRC 正确的记录；不会修复 FAT、恢复损坏文件头或改变原文件。断电可能丢失未同步数据及卡内部缓存，1 秒同步周期不是断电损失上限承诺。

USB 断开或关闭上位机**不会自动停止 GEEK 录制**。原控制会话按原保护过期，通用波形因会话失效不再上送；可能继续收到状态。重连需查询真实录制状态，不自动恢复运动，也不补造断线期间样本。本版没有 ESP 接收端断线本地存储。

## 硬件验收顺序（尚未执行）

1. **核对板型、供电与版本。**确认 GEEK PCB 与 V1.1 参考图相符，接收端使用各后端原接线，所有板共地。先断开驱动/动力电源，仅上逻辑电源；记录实际 MAC、信道和已烧录版本。UART 靶车能力回复不匹配时，停在版本核对，不尝试绕过使能。
2. **核对 64 GB 卡。**在电脑只读查看卡容量、分区和文件系统。当前构建 FatFs 未启用 exFAT；需要已确认兼容的 FAT32 卡。备份卡数据后由用户决定是否另行调整格式；本程序不会执行格式化。64 GB 本身不等于已验证兼容。
3. **无卡基线。**GEEK 不插卡，连接两个节点，观察 10 分钟：原状态/停止确认和实时数据可用；SD 显示未挂载，开始录制返回错误。记录各端循环最大间隔、复位原因和丢包计数。不得因无卡导致重连、看门狗复位或运动解锁。
4. **有卡短录制。**停止状态下插卡/重新挂载，开始 20 秒，再停止。状态应由录制变为停止，目录出现非空 `.twl`。下载并回放，核对通道、单位、序号和时间；CSV 与原始值比较。未启用本地 ADC 时通道 1:2 缺失是预期。
5. **历史管理。**设置短中文备注并刷新核对；用设备/时间过滤导出；只对专门测试记录执行删除，确认其他文件仍在。试读不存在 ID 应报错，不应挂死界面。
6. **压力与停止优先级。**双节点同时开原 GPIO 波形和通用快照，录制至少 30 分钟；对比无录制基线的控制应答与 STOP 确认延迟、循环间隔、WDT/复位及丢帧计数。阈值应按现场控制要求确定；软件测试没有给出真实 RF/SD 性能保证。先无动力，之后才由用户按原机械验收流程逐步验证。
7. **存储故障。**在独立测试卡上验证满卡、写保护/写失败、拔卡：应提示错误并停止录制，控制与 STOP 仍可应答，禁止自动格式化。重新插入后手动挂载、新建记录。实际拔卡检测延迟取决于 SD 驱动，需测量；不要用唯一数据卡做此项。
8. **通信故障。**分别断开 USB、一个 ESP、STM32 或无线干扰：原控制保护应生效；恢复需原 STOP 握手。录制状态查询应一致，图表不能跨断点画成连续采样；不得自动发送运动命令或把离线历史送回控制器。
9. **断电与长期录制。**在测试卡上突然断电，保留原卡镜像后检查文件与 FAT。仅在正常可读文件上尝试有效前缀回放。长时间录制应生成多个分段，停止后都能独立读出；分段的 host 分支已注入测试，实际卡长时行为仍待验收。

测试记录请同时填写：后端/固件哈希、板型、MAC/信道、卡型号/格式、节点数、快照周期、原脉冲流量、控制/STOP 延迟、全部丢包计数和故障现象。只有完成实机步骤后，才能评价实际稳定性。

## 重新构建入口

未配对离线构建（不读取本地配对文件、不接触设备）：

```powershell
python tools/build_capture_firmware.py --work C:/Users/y/Documents/Codex/work/capture-build-new
```

已有构建目录须显式加 `--resume`，源码会重新快照后增量编译。工具路径在脚本开头可调整。本机依赖 ESP-IDF 6.1 与其 Xtensa/RISC-V 工具链。

生成实际配对固件应使用各完整桌面工程原有 `tools/build_dualnow.py --paired`（UART）或 `tools/build_wired.py --target all --paired`（SPI/I²C），指定新的纯 ASCII `--out`，保留并核对三个无线工程本地配对配置；本交付没有代替你验证这些私有配置。不要把本次未配对 BIN 当成已配对成套固件。

新界面打包示例（在已安装 requirements-vue-build.txt 的 Python 环境中）：

```powershell
python tools/build_capture_ui.py --variant UART --out C:/Users/y/Documents/Codex/work/capture-ui-dist-new --work C:/Users/y/Documents/Codex/work/capture-ui-build-new
```

SPI/I²C 分别选择对应 --variant。源码有控制版本差异，不能仅把 UART EXE 复制当作三套相同应用。

模拟 e2e 文件日期基准为1970年的测试时间，测试时清空日期筛选；它不是现场工况记录。
