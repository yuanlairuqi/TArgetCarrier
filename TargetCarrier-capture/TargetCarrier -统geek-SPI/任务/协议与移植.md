# 协议、模块与移植

## 传输路径

GEEK USB ↔ ESP-NOW ↔ 对应 ESP32-S3 ↔ SPI ↔ STM32。直连 BLE 备选方式为 PC BLE ↔ 对应 ESP ↔ SPI ↔ STM；两种 x轴 ESP 工程二选一。无线格式、加密配置、上位机可见字段和原业务应答语义保留。

## 模块边界

| 文件 | 职责及依赖 |
|---|---|
| tc_protocol.c / tc.h | 纯 C 槽编解码、CRC32、有限队列、流/分片辅助；无 UI、电机和引脚依赖 |
| wl_codec.c/h | 32/17 字节旧业务消息封装；节点、会话、序号、回显去重；纯 C |
| esp_bus.c / tc_bus.h | ESP-IDF GPIO、SPI/I²C 事务与有界队列 |
| stm32_bus.c | STM32F103 CMSIS 寄存器、DMA/IRQ适配；SPI1 / DMA1 通道2 RX、通道3 TX；PA4 NSS 上升沿 EXTI4 |
| wl_esp.c/h | ESP 单例 C API、静态互斥锁、随机会话、原始消息读写 |
| wl_stm.c/h | STM 单例 C API、临界区、原始消息读写、错误计数 |
| tc_board.h | Stamp-S3Bat侧边引脚、保留脚和重复检查，接口、速率、地址与轮询配置 |
| wired_esp.cmake / wired_stm.cmake | 注入真实业务工程；WL_NODE=1 为x轴、2为靶车 |
| 原 uart_link / robot_uart / link_uart 适配文件 | 兼容原业务 API；名称保留但实际调用新链路 |

STM32duino仅在 link_uart.cpp 中注册 EXTI 和保留 C API；通信核心、协议、两端驱动仍为 .c/.h。驱动开头“reference firmware”注释继承自原独立示例，当前通过上述 CMake 文件真实编入两组业务工程，详见构建日志和源码一致性校验。

## 最小 API 与接入

```c
/* ESP: 在任务上下文，系统/FreeRTOS 启动后初始化。 */
if (!wl_esp_init()) { /* 保持业务禁止，报告故障 */ }
/* 首包为业务真实 STOP/disarm，safe不能用于普通运动命令。 */
bool queued = wl_esp_send(stop_frame, legacy_length, true);
int bytes = wl_esp_read(rx, sizeof rx);

/* STM: 时钟、HAL tick 和板级基础初始化后，在通信任务中使用。 */
if (!wl_stm_init()) { /* 业务保持禁止 */ }
wl_stm_poll();
unsigned received = wl_stm_read(rx, sizeof rx);
if (wl_stm_bound()) { bool queued = wl_stm_send(reply, legacy_length); }
uint32_t errors = wl_stm_errors();
```

`legacy_length` 必须是当前业务解码器所需长度（x轴32、靶车17），最大32。上面的 stop_frame/reply 是调用者按原协议编码的缓冲区，不能直接复制占位变量编译。可直接编译的完整接入见 x轴两个 uart_link.c、robot_uart.c 和靶车 main.c、link_uart.cpp。

初始化顺序：系统时钟和 tick → 原业务/安全初始化 → wl_*_init → STM32duino SPI attachInterrupt → 通信任务周期性 poll/read → 通过原业务协议检查并应用。初始化失败不可开放运动。`true` 只表示进入发送队列，不代表对端已收、参数已应用或运动已执行；这些继续由原业务 ACK/状态判断。

ESP API 只能在任务上下文调用，通过静态互斥锁串行化发送、轮询和限位 STOP。SPI/I²C 调用可能阻塞；I²C 单次操作超时8 ms，连续读写确认可能累加，不保证8 ms内完成整轮。STM poll/read 是单一通信任务所有；send 以短临界区保护共享队列。IRQ 只处理事务和固定缓冲，不调用RTOS/电机接口。wl_spi_cs_rising 仅用于STM32duino SPI边沿回调。

send 对数据作复制，返回后调用者可复用缓冲；read 向调用者数组复制。固定队列每级 TC_Q=4、每槽128字节，底层按消息类型保留高/低优先队列。高优先队列满时拒绝新增；低优先波形队列可丢最旧；队列取出时丢超过100ms的槽，不无限积压。业务封装全部属于 CONTROL/STATUS，并未新增独立波形采样器。收到有效 STOP/disarm 槽时STM清待处理队列，ESP发送STOP前清待发队列；不能撤回已执行命令。原业务超时/锁止规则继续生效，底层错误计数变化触发原安全处理。

## 128 字节槽协议

所有多字节数值小端。槽 0..1 为 TC，2 为版本2，3 为类型（下行 CONTROL=7，上行 STATUS=6），4..7 session，8..11 seq，12..15 毫秒时间，16..17 total，18 index，19 count，20..21 len，22..27 保留零，28..123为最多96字节数据和零填充，124..127是对0..123计算的CRC32/IEEE（反射多项式0xEDB88320）。

数据区为 `0x4c、node、raw_len、safe、echo_seq(4字节)、raw_payload`。node1=x轴，2=靶车，safe只能0/1；上行 echo_seq 回显最新接受下行的传输序号。旧业务payload自身CRC/序号/会话检查照常执行，不能绕过。当前业务一槽即可，count=1/index=0；不在该封装中承诺长消息分片。tc_protocol.c 有通用分片辅助，独立调参示例另见portable_comms，本次业务不依赖它的参数表。

ESP 启动生成随机 session；STM 对新 session 只有首个带 safe 的 STOP/disarm 槽才绑定。发送序号32位递增并跳过0；用有符号差值判断新旧。STM拒绝重复和乱序下行；ESP拒绝错会话/错节点、未来echo、旧echo以及同echo下的旧/重复状态序号，避免重复读取邮箱维持虚假在线。STM复位后允许新echo对应的状态序号重置。新 ESP owner 仍必须执行原业务STOP握手，safe标志不等于业务命令已验证。

SPI 用固定长度 DMA 事务，不套用串口字节流。四线版在业务任务调用轮询时按至少2ms间隔发送128字节槽，保留一个未确认槽，直到收到正确SA确认或超过100ms；确认必须匹配会话、序号和原槽CRC。STM只在入队成功或精确重传时生成SA帧（TC/2、HELLO类型、数据为ASCII SA和原槽CRC32），重复重传只确认、不重复入队；队列满时不确认。SA表示传输队列接收，不表示参数已应用或动作已执行。收到STOP时ESP清除待发队列和在途槽，STM在接收STOP时清除待处理控制队列；较早的确认不能确认新的STOP。为了不让应答长期挤占状态，STM在发送SA后优先给待发状态一次机会。STM向ESP的状态槽没有单独送达确认，损坏的状态由上层丢弃，依赖后续状态刷新；不能保证每条状态都送达。无独立READY，CRC/确认及有限重发用于检测和恢复部分丢失，不能保证实物上所有DMA/IRQ时序；现场还需测故障恢复、超时和最终停机行为。I²C 用读写邮箱和独立 `AK,version2,0,seq32,slotCRC32` 12字节确认，表示邮箱交付，不等于业务应用。CRC无效不确认；丢确认可重读，业务层去重。主机事务失败计数后等待业务刷新/超时；没有无限重试和自动切换。驱动有限队列和100ms年龄限制不取代原运动命令租约和超时停机。

本版总线封装与原 UART 固件不兼容，双方必须一起升级；内层 USB/BLE/ESP-NOW格式保持原版本。控制、参数应用、业务执行三种状态不能用总线 ACK 混为一谈。

## 带宽预算与建议值

建议初始SPI 1MHz、I²C400kHz、最小轮询间隔2ms、每级4槽。这些是本版配置选择，不是已确认性能指标或实测结论。现有任务调用频率、无线调度、时钟伸展和RTOS抢占都会进一步限制吞吐。

- 每个旧消息固定占128字节：x轴载荷效率32/128=25%，靶车17/128≈13.3%；将来批量波形应重新设计批处理，不能直接据此承诺高采样率。
- SPI一事务线路时间128×8/1MHz=1.024ms，可同时收发；不含CS间隔和软件开销。2ms轮询至多500个槽/秒；四线版下行新消息至少占两次槽交换（发送及接收确认），因此理想上限约250条新消息/秒，即x轴32字节约8kB/s、靶车17字节约4.25kB/s。重传、状态、公用无线、任务调度都会使实际值更低；均为理论预算。
- I²C一轮下行128+上行128+确认12字节，加三个地址字节，至少(268+3)×9/400k≈6.10ms，不含START/STOP/延迟/伸展。此全双向业务轮次理论上限约164轮/秒，不能因2ms轮询就声称500轮/秒。
- 波形需求计算：通道数C×每样本字节B×采样率F，加时间戳/通道/分包头；再按每槽有效载荷与总线事务开销换算线路占用，并叠加命令/状态频率，预留余量。建议初始仅用预算的一半，测最差延迟和丢弃数后再增加，未规定用户目标C/F/延迟。

## 本次板型修正

根据用户S3BAT照片与官方文档重选引脚：SPI SCK/MOSI/MISO/CS=3/4/5/11（四线，无READY）；I²C SDA/SCL/DRDY=4/5/11。原GPIO1/2限位、6/7采集、8/9 OLED及G10用户输出保留。SPI取消独立READY，并新增传输层SA确认、限时重发与去重；STM的PB1不再用于SPI。内层业务格式、1MHz速率不变；新SPI与之前五线版本必须成对更新。两个副本的五个受共享配置影响的业务固件工程均重新编译，GEEK源码不受本次修正影响，沿用之前已验证构建产物。

官方板卡为8MB Flash/8MB PSRAM；既有从机配置使用4MB Flash布局且未启用PSRAM，布局在8MB器件范围内。本次保持既有存储配置，不声称已经初始化或利用全部板载存储。

## 后续移植替换点

纯C codec和旧业务协议可复用；需替换芯片寄存器头、HCLK/PCLK设置、HAL_GetTick时间源、GPIO、DMA通道、IRQ入口和STM32duino注册方式。tc_board.h中的ESP引脚可配置；STM引脚/寄存器目前在stm32_bus.c，是明确的F103参考实现，不能只改宏就迁移其他STM系列。新平台应先跑主机测试，再分别编译和验收物理总线。新业务可替换17/32字节payload上层编码，但需要双方同步变更并记录协议版本。
