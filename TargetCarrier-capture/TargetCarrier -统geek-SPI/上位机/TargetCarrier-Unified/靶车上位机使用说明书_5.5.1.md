# 靶车上位机使用说明书 5.5.1

2026-10-26


## 01 先读这一页：当前交付与使用边界

适用：TargetCarrier 靶车控制台 5.5.1，配套本次 VMAX45 版 STM32 源码和固件。日期：2026-10-26。用户确认电机称为 DM6220、24V 供电；完整铭牌、电压版本、实际供电质量和机械安全行程尚未独立核实。

> 当前尚未烧录 VMAX45 固件，尚未验证电机正常转动。请保持失能；不要把更新源码、编译通过或电机“已使能”回报当成机械动作验收。

|项目|本次结果|
|---|---|
|实际链路|电脑 BLE → TC-Target 桥接 ESP → UART → STM32 → CAN → 电机驱动|
|电机实际回读|PMAX 12.5；VMAX 45；TMAX 10；CTRL_MODE 原始值 1|
|已发现不一致|原 STM32 源码 VMAX=30；本次已改为 45 并构建，尚未烧录|
|上位机保护|默认 kp/kd=0；使能前核对量程、人工确认已烧录、明确应用增益|
|尚未确认|安全偏转角、可用低速、负载增益；振动的全部原因|

### 发生震动时

立即点击“靶车急停 / 失能”或“全部停止”；若停止指令无效或仍有危险，切断电机驱动电源。不要用反复使能、反向命令或盲目加大增益尝试排除震动。

本说明书的操作顺序是：安装与连接 → 读配置 → 确认固件匹配 → 明确设置增益 → 手动解除急停 → 手动使能保持当前位置 → 在安全范围已确认后下发新动作。


## 02 启动、连接与设备识别

### 启动入口

关闭旧版控制台，使用指定桌面工程内“启动通信诊断版5.5.1.lnk”或“启动统一控制台.lnk”。确认窗口标题为“TargetCarrier · 双 BLE 直连控制台 5.5.1”。EXE 与同目录 _internal 必须一起保存。

工程根目录：C:\Users\y\Desktop\TargetCarrier -统筹程序运行

上位机目录：C:\Users\y\Desktop\TargetCarrier -统筹程序运行\上位机\TargetCarrier-Unified

应用相对目录：app\TargetCarrier-Unified-5.5.1\TargetCarrier-Unified.exe。D:\达妙电机上位机 只是本次参考目录，不是本控制台的启动目录。

### 连接步骤

1. 保持电机失能，确认通信板已上电。进入左侧“靶车控制”，点击“搜索靶车”。

2. 选择 TC-Target，再点击“连接并锁定”。本次读到地址 AC:27:6E:D3:32:82，控制服务 UUID 为 6e410001-b5a3-f393-e0a9-e50e24dcca9e；软件还会核对真实服务，不能只凭同名设备判断。

3. 分别查看 BLE 在线、STM32 反馈年龄、电机反馈年龄和原始状态。新连接只请求停止，不恢复旧角度、速度、巡航或程序。

|连接表现|处理|
|---|---|
|未搜索到|检查通信板上电、是否被其他客户端占用，再搜索；不要改 Windows 驱动/注册表试错。|
|BLE 在线、STM32 过期|检查 UART 两方向、共地及配置。当前源码 UART 为 921600 8N1；不能据此证明实测波特率正确。|
|STM32 在线、电机过期|检查电机供电、CAN 接线、ID、终端和驱动报警。|
|故障锁定|先查原因；反馈失能、零速且链路正常后才允许手动清错。|


## 03 使能前：核对量程、固件与增益

> 当前设备还没有由本任务烧录新固件。请先由用户按既有 SWD 流程烧入靶车 STM32 的 firmware.hex 并重启；不要烧到 x 轴或 ESP。BIN 如需使用，起始地址为 0x08000000。

配套固件相对上位机目录：firmware\靶车_STM32_VMAX45_20261026\firmware.hex。源码位于工程内 靶车\靶车\firmware\stm32_f103\include\config.h。本次只把 MOTOR_VMAX 改为 45，并保留其他已有修改。

### 操作顺序

1. 保持失能，点击“先读取电机配置”。检查 PMAX=12.5、VMAX=45、TMAX=10；CTRL_MODE 显示的是原始寄存器值，还需结合实际电机/驱动模式核对。软件不自动改写模式或映射量程。

2. 只有实际烧录了本次 VMAX45 版，才点击“确认 STM32 已实际烧录 VMAX45 版”。该按钮只记录人工确认，不执行烧录，不会解除急停或使能；重连后需要重新核对。

3. 在失能状态设置经确认适合当前负载的 kp/kd，点击“失能时应用增益”。默认 0/0 不允许使能；位置控制需要有效阻尼，程序允许 kd 最小 0.01。不要把示例或旧版 60/1.5 当成通用整定值。

4. 如仍有故障锁存，先排查，再手动“清除故障（保持失能）”。清错需等真实反馈确认；若再次出现故障，不继续使能。

5. 点击“解除急停”，等回报。最后点击“使能靶车”。此时软件重新采用最新实际位置并清空旧轨迹/速度，只请求保持当前位置。

|常见禁用原因|必须满足的条件|
|---|---|
|配置未读或量程不一致|先成功读回，并使电机与已烧录固件量程一致|
|尚未确认新固件|先实际烧录，再人工确认；修改源码不够|
|kp/kd 为0或尚未发送|明确应用有效增益；GATT 接收仍不等于固件采用值回读|
|失能/零速/授权未确认|等待新鲜反馈；不得绕过保护|


## 04 角度、速度、轨迹及并行程序

> 当前未确认允许的低速和最大机械偏转角。本次没有进行运动验收。以下说明功能用法，不是对未知机械系统的试转授权或参数建议。

|功能|使用方法与含义|
|---|---|
|角度控制|使能后输入 yaw/pitch，点击“下发角度（使能后）”。单位 °；靶车当前 STM32 为单轴 yaw，不能把 pitch 下发当成已有第二轴运动。|
|速度模式|输入 yaw/pitch 角速度并应用。单位 °/s；电脑生成位置轨迹并发送相应速度目标。|
|增益|只在失能状态应用；kp/kd 是 MIT 闭环增益，不是供电电压、电机电流或驱动器内部所有 PID 参数。|
|全部停止|向两端分别发停止请求；设备断联时停止结果未知。|

### 六种轨迹均保留

|编号/模式|用途|
|---|---|
|0 STATIC|静态目标|
|1 SINE|正弦轨迹，幅度 °、周期 s|
|2 SWEEP|往返扫描，幅度 °、速度 °/s|
|3 CIRCLE|原有圆周轨迹逻辑；当前单轴固件只驱动 yaw|
|4 FIGURE8|原有八字轨迹逻辑；实际可执行轴以固件和接线为准|
|5 MANUAL|手动目标、速度和巡航控制|

使能前预设的动作不会因点击使能自动执行；使能后需要明确下发新角度、速度或轨迹。界面 ±180° 等软件范围不是已确认的机械安全行程。

“并行程序”保留 x 轴与靶车两条程序线、动作/等待模块、运行中追加和停止。启动仍需本端配置、固件及增益检查通过；故障会联停，不自动重放旧程序。定时结束依据控制器反馈，不构成机械动作测量。


## 05 状态、波形与数据导出

|显示项|正确解读|
|---|---|
|请求使能 / 急停|电脑当前意图，与电机真实反馈分开显示|
|原始电机状态码|0=失能，1=使能，≥8=电机故障；原始1不是故障码|
|STM32 状态|0待机、1工作、2控制超时、3急停、4故障锁存|
|反馈年龄|STM32 / 电机分别判断；BLE 在线不能替代两者在线|
|GATT 往返 / 控制间隔|用于定位发送拥堵，不是 CAN 或 GPIO 电气测量|
|UART 异常 / 控制丢帧|各自固件暴露的计数；不等于整条链路的完整丢包统计|

### 波形开关

“显示偏航波形”只开关电脑端绘图，不停止设备采样，也不切换运动模式。曲线显示转发的 yaw，最近约30秒；数据缓冲有上限，后台控制仍独立执行。断线或历史数据应按界面标识解读。

脉冲采集页面属于原有 x 轴链路。本次故障端是 CAN 云台，不能用该页面推断靶车 PUL/DIR，也不能把 yaw 曲线当示波器波形。

### 导出

“导出 CSV”和“导出双设备诊断”保留。现有导出流程会先请求两端全部停止，并把状态标为相应历史/当前数据；请在停机分析时使用。日志位于当前 EXE 所在目录的 logs\connection.log。

诊断会记录操作参数、报文、GATT 时延、状态年龄及配置读取结果。增益仅标为已发送，因为现有 STM32 协议不回传 kp/kd 采用值。不要把此项误读为已完成增益闭环核验。


## 06 参数读取、写入及回读核对

参数通道复用当前桥接固件已有 PARAM 报文，保持单事务排队。运动命令不会因参数超时自动重发；读取最多重试一次；参数写入只发送一次。

|操作|步骤与结果|
|---|---|
|读取配置|一次读取 RID10、21、22、23，保留模式/量程核对结果|
|读取参数|填写十进制 RID 和正确类型，再读取；看数值及原始4字节|
|写入并回读|先读取原值；明确填写合法新值。写入回复到达后，再发独立 READ 比较|
|回读一致|说明返回字节与目标一致；未执行掉电保存，机械效果尚未验证|
|回读不一致/超时|未确认生效；不自动补写，不因 GATT ACK 显示成功|

### 本次实际读到的例子

RID6 MAX_SPD 回读为 float32 40.0，原始字节 00002042。它与 MIT 映射 VMAX（RID22，本次回读45）是不同参数，不能把两者混用。RID10 用 uint32；PMAX/VMAX/TMAX 用 float32。

界面不自动填写写入值。RID6 的0或负数等非法值会在发送前被拒绝；类型错误也会拒绝。模式、CAN ID、Master ID 和映射量程禁止经本页面改写，避免与已烧录固件失配。

当前允许写入的寄存器为 RID0、1、2、3、4、5、6、9、24、25、26、27、28、30、31；RID9 使用 uint32，其余使用 float32，并检查手册范围。是否适合具体电机仍需核对铭牌和固件。

本轮自动联调只读参数，没有写电机寄存器或执行保存。用户在旧5.5界面尝试向 RID6 写0后，独立回读仍为40，界面已报告不一致；最终5.5.1已在发送前禁止该非法值。

TC/2通用调参独立入口仍保留，使用它自己的 USB 固件与协议。当前未枚举到对应 USB 通信板，本轮没有把它冒充为靶车 CAN 调参通道。


## 07 故障排查与断联恢复

|现象|排查重点|
|---|---|
|刚使能即震动|先失能。核对映射量程、实际位置/零点、增益及负载，再检查供电和驱动器内部参数；不能只归因于通信。|
|只震不转|检查是否追逐旧目标、是否有持续启停/方向切换、驱动报警、限流、机械卡滞、相线与编码器问题。|
|量程不一致|核对已烧录版本与电机回读；本次已构建 VMAX45，未自动修改电机内部量程。|
|断联|软件退避重连，旧运动作废；恢复后重新核对配置、固件确认及新启动命令。|
|CAN失败计数较大|区分历史累计与本次增量。本次观测1972保持不变，不能据此排除带载时的电气问题。|

### 安全位（可组合，相加显示）

1授权；2使能；4急停；8故障锁存；16电机反馈过期；32 CAN恢复；64控制链路超时；128授权拒绝。比如12=急停4+故障8，并不是电机原始故障12。

### 需要的人工检查和仪器

供电：用万用表核对实际电压，必要时用示波器/电源记录观察使能时压降与限流。CAN：由熟悉接线人员检查 CAN_H/L、共地、终端、驱动报警；需要时用 CAN 分析仪测量帧、重发和错误。

相线/编码器/校准：核对准确型号和厂商接线资料。不要在行程未知时启动自动校准，校准可能产生大范围运动。当前没有实际电气波形或编码器接线测量结果。

PUL/DIR不在本次实测 CAN 路径中。若后续排查 x 轴，必须用示波器或逻辑分析仪实测频率、数量、脉宽、DIR 建立/保持及加减速，不能由日志代替。
