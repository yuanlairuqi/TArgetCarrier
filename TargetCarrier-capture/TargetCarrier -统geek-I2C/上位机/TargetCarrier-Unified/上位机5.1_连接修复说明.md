# 上位机 5.1 连接修复（2026-10-25）

启动：D:\TargetCarrier-Parallel\启动统一控制台.lnk 或 启动连接修复版5.1.lnk。
独立应用目录：app/TargetCarrier-Unified-5.1，EXE 必须与 _internal 一起保存。
旧 5.0 保留，旧启动入口备份于 _backups/连接修复_5.1_20261025。
关闭正在运行的旧版窗口，再使用新版连接同一台设备，避免多个客户端占用。

## 修复内容

- 两端统一先枚举全部 GATT 服务，再核对控制 UUID，避开原有按 UUID 查询 API 的 WinError 0x80070016。
- 首次刷新服务数据库；失败后释放旧客户端，以 Windows 默认缓存策略重新枚举一次；每次连接限时 20 秒。
- 服务缺失仍明确拒绝，不因为设备同名而允许控制。扫描兼容 TC-XAxis、旧 ESP32-Robot、TC-Target 名称。
- 两端独立显示链路/控制就绪状态；不把 STM32 未就绪混为蓝牙未连接。
- 新增 x 轴取消连接/搜索；靶车取消期间正确释放并保留会话占位，避免旧清理覆盖新连接。
- 建立状态通道后解除“处理中”，保留具体失败原因、重试阶段和日志；停止确认仍独立校验。
- 搜索失败/取消立即清空旧候选；蓝牙关闭等错误不会再被 USB 的普通选择提示覆盖。
- 双线并行、运行中追加、全部停止、限位锁存及复位保护继续保留。

## 本轮验证

178 项完整回归通过，包含扫描失败、取消、服务发现兼容和并行程序；25 项目标 BLE 测试复测通过；EXE 打包成功。
对真实 x 轴 TC-XAxis 进行了只读验证：约 1.1 秒成功枚举控制服务，读到合法状态帧，并在 1 秒内收到 11 条通知。
探测没有 write_gatt_char，没有运动、解除限位、使能或烧录操作。
该设备当时回报 error=10（限位锁定）、STM32 online=false、停止反馈未确认，状态协议版本为3。
因此已验证这台 ESP 的 BLE 连接/状态通道恢复；下游 STM32 与限位问题仍需检查，不能据此认定电机可运行。
本轮未扫描到 TC-Target，靶车使用了同一连接修复，但尚未实机验证。
完整证据见 verification/live-probe.json 和 live-probe.log。

## 使用

1. x 轴页搜索 TC-XAxis，连接后先看“链路在线”和 STM32/限位提示。
2. 靶车控制页单独搜索 TC-Target，再连接；蓝牙在线和 STM32 新鲜反馈分别显示。
3. x 轴限位必须释放两路输入、确认 STM32 停止后手动复位。不要为连接测试启动运动。
4. 失败时保留 logs/connection.log；日志区分服务枚举、UUID校验、通知订阅与下游状态。

本轮只更新上位机，无需为本轮软件修复重新烧录 ESP；靶车若仍用旧 ESP-NOW 固件，仍需先前交付的靶车 BLE 固件。
没有修改 Windows 注册表、驱动、服务或系统蓝牙设置；既有 usb.local.json 保留，不放入公开交付压缩包。
