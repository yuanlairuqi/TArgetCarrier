# 网页控制台（手机 / 电脑浏览器）

主机（ESP32-S3，`firmware/esp32_master`）自带一个 WiFi 热点和网页服务：
**手机或电脑连上热点 → 浏览器打开 `http://192.168.4.1`** 就能控制云台，不用装 App。

```
手机/电脑浏览器  ──WiFi(热点)──►  ESP32 主机  ──ESP-NOW──►  M5Stamp 桥接  ──UART──►  STM32  ──CAN──►  DM-G6220
                                     ↑ 网页 + 串口控制台共用同一套命令
```

## 一、第一次使用

1. 烧主机固件：

   ```powershell
   cd 靶车\firmware\esp32_master
   $env:ESP32_PORT = "COMxx"
   cmake --build --preset esp32-master --target flash
   ```

2. 给主机上电，串口（460800）应看到：

   ```
   [ESP-NOW] 就绪, 信道=6, 本机MAC=D4:05:92:77:C1:B8
   [WEB] 热点 "TargetCar" 密码 "target123" 信道=6
   [WEB] 手机/电脑连上热点后打开 http://192.168.4.1
   ```

3. 手机/电脑的 WiFi 列表里连 **`TargetCar`**，密码 **`target123`**。
   （这个热点没有外网，连上后手机可能提示"无互联网"，选择"保持连接"即可。）

4. 浏览器（Chrome / Safari / Edge 都行）打开 **`http://192.168.4.1`**。

## 二、界面上有什么

| 区域 | 作用 | 对应串口命令 |
|---|---|---|
| 状态卡片 | 主机逻辑状态（失能/使能/急停）、轨迹、提交计数、目标 yaw/pitch、kp/kd | `s` |
| 使能 / 失能 | 电机会不会出力（**上电默认失能**；断链/急停/故障后需重新点使能） | `E` / `C` |
| 急停 / 解除 | 立即断使能并持续下发 ESTOP；解除急停**只清急停**，不会恢复使能 | `x` / `R` |
| 运动授权 / 安全 | 显示 `safe`（链路安全锁）/`safe_reason`、`arm`（是否已授权）、`arm_token`、`arm_rej` | `s` |
| 通信诊断 | `tx_sub_ok/fail`（提交）、`tx_cb_ok/fail`（回调）、`tx_confirm`（应用确认）、`cb_timeout`、`q_drop`、`cmd_age_drop`；丢包率只用回调算 | `s` |
| 0~5 轨迹 | 定点 / 正弦 / 三角扫描 / 圆周 / 八字 / 手动 | `0`~`5` |
| 滑块：a / t / k / d | 正弦幅度、正弦周期、kp、kd（松手才下发） | `a 30`、`t 4`、`k 40`、`d 1.2` |
| 手动 y / p | 直接给偏航/俯仰角度（自动切手动模式） | `y 10`、`p -5` |
| 清错误 / 存零点 | `e` / `z`（存零点会二次确认） | `e` / `z` |
| 保存参数 / 刷新状态 | 立刻把当前参数写 Flash / 手动刷新一次 | `w` / `s` |

状态通过 WebSocket 以 20 Hz 推送（同一份 JSON），WebSocket 断开时退回 **HTTP 轮询 500 ms**；
按钮点击即生效，滑块拖动过程只更新数值、松手才发送（避免刷屏）。

### 2.1 状态字段与「授权」语义（协议 v1.1）

- **`st_fresh` / `st_online` / `st_age`**：STM32 反馈是否新鲜。页面按
  `protocol.h` 的 `proto_link_state_t` 显示状态：
  `0 INIT/等待`、`1 OK/使能`、`2 TIMEOUT/失联超时`、`3 ESTOP/急停`、`4 FAULT/故障`，
  再叠加新鲜度：**`st_fresh=0` 时显示"过期/离线（xx ms）"，不会把缓存数据写成"实时"**。
- **`br_age` / `br_flags`**：桥接 100 ms 新鲜度帧（0x07）报告的 STM32 反馈年龄与链路标志
  （`STM_FRESH` / `FAILSAFE` / `HAVE_STM` / `MOTION_BLOCKED` / `UPLINK_READY` /
  `STM_ESTOP` / `RX_OVERFLOW`）。桥接**只在 STM32 反馈 ≤300 ms 时转发状态帧，不再重发缓存**。
- **`safe` / `safe_reason`**：主机安全锁。`safe_reason` 是**单个原因码**（不是位掩码）：
  `1`=无线/桥接链路失效（桥接新鲜度帧或 STM32 状态超过 300 ms），
  `2`=STM32 反馈过期（数据还在但已老），
  `3`=ESP-NOW 发送回调超时（在途 250 ms 未回调），
  `4`=桥接 FAILSAFE / 拒绝使能（motion blocked），
  `5`=其它（如 RTOS/内部错误，需看串口日志）。
  **`safe=1` 时"使能"按钮禁用，并提示"链路恢复后需重新使能"**——链路恢复不会自动恢复运动。
- **`arm` / `arm_token` / `arm_rej`**：运动授权状态。`arm=1` 表示当前有有效授权、
  `arm_token` 是本次授权的 8 bit 令牌，**用户每点一次"使能"才会生成新令牌**；
  旧令牌永远不能重放（断联/急停/故障/总线恢复后，即使旧 ENABLE 帧还在路上也不会重新使能）。
- 急停/停止按钮**在任何状态（safe/离线）下都可用**，命令会走旁路通道尽力送达。

### 2.2 通信诊断字段（提交 ≠ 回调 ≠ 确认）

| 字段 | 含义 |
|---|---|
| `tx_sub_ok` / `tx_sub_fail` | `esp_now_send()` 提交结果（**只代表交给 WiFi 层**） |
| `tx_cb_ok` / `tx_cb_fail` | 发送完成回调结果（对方是否收到） |
| `tx_confirm` | 应用层确认：桥接 0x07 帧/STM32 状态帧回报已收到 |
| `cb_timeout` | 在途超过 250 ms 未回调的次数 |
| `q_drop` | 主机 WS 命令队列满丢弃数（安全命令不走该队列） |
| `cmd_age_drop` | 过期命令丢弃数（>100 ms） |

页面上的**丢包率只按回调结果计算**：`cb_fail / (cb_ok + cb_fail)`；没有回调数据时显示 `--`，
**绝不用提交计数冒充成功率**。

## 三、参数掉电保存（NVS）

调好的参数会写进 Flash，**下次上电自动恢复**，不用每次重调。

| 会保存 | 不保存（故意的） |
|---|---|
| `kp`、`kd` | 使能位（`ENABLE`） |
| 正弦幅度 `a`、周期 `t` | 急停标志 |
| 扫描幅度 `A`、角速度 `v` | 当前轨迹模式（上电固定"定点"） |
| 圆周半径 `r` | 手动角度 y/p |

> 为什么不存使能/轨迹：一上电就闭环摆动太危险。上电永远是"失能 + 定点 0°"，
> 确认现场安全后再点"使能"。

**怎么触发保存**

- 自动：改过上面任一参数后 **1.5 s** 内没有新改动，就自动写一次 Flash（连续拖滑块只会写一次）。
- 手动：串口/网页发 `w` 立刻保存。

串口会打印确认：

```
>> 参数已保存到 Flash: kp=45.0 kd=1.20 a=15 t=4.0 A=40 v=15 r=20
```

下次上电启动时：

```
[NVS] 已加载参数: kp=45.0 kd=1.20 a=15 t=4.0 A=40 v=15 r=20
```

**实现细节**（[param_store.h](靶车/firmware/esp32_master/include/param_store.h) / [param_store.cpp](靶车/firmware/esp32_master/src/param_store.cpp)）：用 IDF 原生 NVS，namespace `targetcar`、key `params`，整个结构体作为一个 blob 存，带魔数 `TCR2` 校验；字段有变化就把魔数改一下，旧数据会被安全丢弃而不是被误读。范围在读取时会再按命令行的取值范围夹一次，防止 Flash 里是旧版的怪值。

## 四、和串口控制台的关系

- **同一套命令**：网页调用的是主机里的 `handle_command()`，和串口敲的是同一条路径，所以两边行为永远一致，可以一边看串口日志、一边用手机点按钮。
- 网页只是"遥控器"，**所有安全机制不变**：
  - 失联保护：主机 SAFE 300 ms（桥接帧/STM32 状态过期）、桥接 FAILSAFE 300 ms（每 50 ms 注入失能帧）、STM32 独立 300 ms 控制超时（**没有 1000 ms 宽限**）；
  - 命令过期 100 ms、ESP-NOW 在途回调超时 250 ms、增益 500 ms 斜坡、急停优先级最高；
  - **运动授权**：只有用户明确点"使能"才发 ARM 令牌；断联/急停/故障/CAN 恢复/复位后一律撤销授权，恢复链路也**不会**自动恢复运动，必须重新点使能。
- 网页/浏览器关闭**不会**停止自主轨迹（这是主机的既有设计）；需要停车请用急停/停止或物理断电。

## 五、连家里 WiFi（不用切热点）

不想每次把手机切到 `TargetCar` 热点？让主机（和桥接）连到家里的 2.4G WiFi，
之后**手机/电脑在同一个 WiFi 下直接打开主机的 IP** 就行。

1. 手机先连一次热点 `TargetCar`，浏览器打开 `http://192.168.4.1/wifi`；
2. 填家里的 **2.4G** SSID 和密码 → 保存 → 主机自动重启去连接；
3. 连上后串口会打印：

   ```
   [WiFi] 已连上 "rm_2.4G", IP=192.168.1.23, 信道=6
   [WEB] 手机/电脑连同一个 WiFi, 打开 http://192.168.1.23/
   ```

4. **桥接板也要连同一个 WiFi**（插上 USB，串口发 `J <名>,<密码>`，自动重启）。
   两块板在同一个 WiFi 后，ESP-NOW 的信道自动跟随路由器，两端自动一致；
   只连一块的话另一块还在信道 6，链路会断。

命令行等价（主机/桥接通用）：

```
J rm_2.4G,mypassword      # 存 WiFi 账号并重启（密码至少 8 位）
D                         # 清除账号，退回热点 / 固定信道 6
b                         # 重启
```

连不上会自动退回热点 `TargetCar`，不会把自己锁死。

## 六、可配置项（`firmware/esp32_master/include/app_config.h`）

```c
#define WEB_UI_ENABLE   1              /* 0 = 关掉网页/热点, 回到纯 STA 模式 */
#define WEB_AP_SSID     "TargetCar"
#define WEB_AP_PASS     "target123"    /* 至少 8 位 */
#define WEB_AP_CHANNEL  ESPNOW_CHANNEL /* ★ 必须与 ESP-NOW 同信道(6) */
```

> ★ 热点信道不能随便改：ESP-NOW 和 WiFi 共用同一个射频，热点开在别的信道会把
> ESP-NOW 直接切走，表现为桥接立刻"失联"。

## 七、安全说明

- 热点是 WPA2 加密的，但 **API 本身没有登录**：能连上这个热点的人就能控制云台。
  现场用没问题；如果担心，把 `WEB_AP_PASS` 改复杂，或者 `WEB_UI_ENABLE 0` 关掉。
- 网页上的"急停"是软件急停（走控制帧），**物理断电才是最可靠的急停**；调试带负载的云台时手边要能随时拔 24 V。
- **解除急停 `R` 只清急停锁存，不会恢复使能**；急停解除后必须重新点"使能"（生成新 ARM 令牌）。
- **链路恢复不会自动恢复运动**：断联/桥接 FAILSAFE/STM32 反馈超时进入 `safe=1` 后，即使链路恢复，
  也必须在网页上重新点"使能"，这是 v1.1 的刻意设计（防止云台自己动起来）。
- 手机连热点后没有外网，属于正常现象（热点只做局域网控制）。

## 八、打不开页面时依次排查

1. 手机是否连的是 `TargetCar`（不是家里的 WiFi）；
2. 串口是否打印了 `[WEB] 热点 ... 打开 http://192.168.4.1`（没有就是没烧到新固件）；
3. 地址是否敲成了 `https://`（必须是 `http://`）；
4. 路由器/系统是否把"无互联网的 WiFi"自动切走（关掉手机的"智能网络切换"）；
5. 页面能开但按钮没反应 → 看串口有没有命令回显、`TX ok` 有没有继续涨。

## 九、实时曲线 · WebSocket 推送 · 参数预设

### 9.1 数据通道

| 通道 | 地址 | 用途 |
|---|---|---|
| HTTP | `http://<IP>/api/status` | 轮询（500 ms），**只在 WebSocket 连不上时启用** |
| WebSocket | `ws://<IP>:81/` | 20 Hz 推送同一份状态 JSON，给实时曲线用 |
| HTTP | `http://<IP>/api/cmd?c=…` | 下发命令（网页按钮都走这里） |

页面启动先连 WebSocket：连上则停用轮询（曲线右上角显示 `WebSocket 20Hz`），断开后自动重连，
重连失败则退回 `HTTP 轮询`——所以**推送挂了页面也不会瞎**。

WebSocket 服务是自写的极简实现（只做握手 + 文本帧 + ping/pong）：
- 协议工具：`firmware/esp32_master/src/ws_proto.c`（纯 C，可主机端测试）
- 服务与任务：`firmware/esp32_master/src/ws_server.cpp`（端口 81，**5120 B 栈**，核心 0，低优先级；
  发送缓冲 `WS_TX_BUF=1024`、状态 JSON 缓冲 1024 B）
- 单元测试：`firmware/esp32_master/test/ws_proto_test.c`（SHA-1/Base64/握手/帧，含 RFC 6455 向量）
- 状态 JSON 在旧字段基础上**只增不改**：新增 `st_fresh`/`st_online`/`br_age`/`br_flags`/
  `safe`/`safe_reason`/`arm`/`arm_token`/`arm_rej`/`q_drop`/`tx_sub_ok`/`tx_sub_fail`/
  `tx_cb_ok`/`tx_cb_fail`/`tx_confirm`/`cb_timeout`/`cmd_age_drop`（总长度 <1000 B）。

```powershell
ctest --preset all        # 跑 protocol_selftest + ws_proto_selftest + linkcore_selftest
```

### 9.2 实时曲线

组件 `<tc-chart>`：canvas 绘制最近 **300 点（20 Hz ≈ 15 秒；HTTP 轮询时约 2.5 分钟）** 的
yaw（蓝）与 pitch（绿），自动量程、DPR 自适应，不依赖任何图表库。

### 9.3 参数预设（4 个槽位，存 NVS）

| 接口 | 作用 |
|---|---|
| `GET /api/presets` | 列出所有槽位（名称、kp/kd/幅度…） |
| `GET /api/preset/save?i=0&name=xxx` | 把**当前参数**存进第 i 槽 |
| `GET /api/preset/load?i=0` | 把第 i 槽应用到当前，并持久化 |
| `GET /api/preset/del?i=0` | 删除第 i 槽 |

页面上是 `<tc-presets>` 组件：4 行槽位，每行「保存 / 加载 / 删」，名字可改；
保存/加载会立即刷新列表。预设存在 NVS（`pre1`..`pre4`），掉电不丢。

### 9.4 本地开发（不烧板子改页面）

```powershell
python 靶车\tools\web_dev_server.py      # http://127.0.0.1:8000/
```

dev server 模拟了 `/api/status`、`/api/cmd`、`/api/presets`、`/api/preset/*`，还实现了
**`/ws` 的 WebSocket 推送**（20 Hz），所以曲线、预设、按钮都能在连板子之前在浏览器里调通。
## 十、稳定性与调参安全（2026-10-21 加固）

### 10.1 开机不再等 WiFi（打开页面卡很久的根因）

以前 `wifi_start()` 会**先阻塞等路由器最多 12 秒**，等不到才开热点。手机在这段时间连上去
拿不到 IP，浏览器就一直转圈。

现在：**热点第一件事就开**，连路由器改成后台重试（每 8 秒一次，不阻塞任何东西）；
连上后热点和 ESP-NOW 的信道会自动跟随路由器（`wifi_poll()` 里做）。

### 10.2 调参安全（防止手滑烧电机）

| 保护 | 位置 | 行为 |
|---|---|---|
| kp / kd 硬上限 | 主机 `app_config.h`：`GIMBAL_KP_SAFE_MAX=200`、`GIMBAL_KD_SAFE_MAX=3` | 串口/网页/预设超过会被**夹住并打印提示** |
| 使能前置检查 | 主机 `case 'E'` | 急停中、kp=0、kp 超限、kd<0.1、**桥接或 STM32 不新鲜**一律拒绝并说明原因 |
| **运动授权（v1.1）** | 主机 `lc_arm_tx_t g_arm` + STM32 `lc_arm_t` | 只有用户点"使能"才生成新令牌；断联/急停/故障/CAN 恢复/复位后撤销授权，**旧令牌不能重放**，链路恢复不自动恢复运动 |
| **链路 SAFE（v1.1）** | 主机 `g_safe`/`g_safe_reason` | 桥接/STM32 超 300 ms、桥接 FAILSAFE/MOTION_BLOCKED、ESP-NOW 在途连续超时 → 撤销 ENABLE/ARM、清队列；`safe=1` 时使能按钮禁用 |
| 增益真正下发 | `PROTO_MSG_GAINS` 帧（17 字节，4 Hz + 改动即发） | 桥接透传，STM32 `app_set_gains()` 应用 |
| STM32 侧再夹一次 | `app_set_gains()` 按 `MOTOR_KP_MAX/MOTOR_KD_MAX` | 坏帧/手改也进不了失控区间 |
| 增益平滑 | STM32 1 kHz 控制环的 500 ms 增益斜坡 | 在线改参不会一步跳变 |
| 网页滑块 | kd 上限改 3 | 与安全上限一致 |

> ★ 注意：`PROTO_MSG_GAINS`、ARM/令牌、桥接 0x07 帧都是协议 v1.1 新增内容，
> **主机、桥接、STM32 必须三端一起重烧**。旧固件会忽略未知帧/未知位，不会立刻报错，
> 但会**静默丢掉安全语义**（例如旧 STM32 不认识 ARM，仍按持续 ENABLE 使能）——禁止只升级一端。

### 10.3 其他加固

- WebSocket 收到的命令走队列交给主循环执行（不跨核心改状态）；
- WebSocket 客户端写超时 200 ms，卡死的客户端会被踢掉；
- 状态 JSON 带上 `up`（运行秒）、`heap`（空闲内存）、`ch`（信道）、`ws`（是否 WS），
  页面"设备"一行直接显示，便于长期跑的时候看有没有内存泄漏；
- 开机打印复位原因与空闲内存，掉电重启/看门狗复位一眼能看出来。
