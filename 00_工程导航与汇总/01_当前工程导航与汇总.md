# TargetCarrier 当前工程导航与汇总

整理日期为 2026 年 11 月 11 日。本文依据当时磁盘中的文件夹整理，适合查找工程、上位机、接线与测试资料。各目录可能包含不同日期的源码和历史产物，实际设备的接线、固件及配对状态需另行核对。

## 1 工程结构

```text
TargetCarrier -geek
├─ README.md                     工程简要说明
├─ 00_工程导航与汇总
│  ├─ 01_当前工程导航与汇总.md   本文
│  └─ 录波源码和测试文件recorder_core
├─ 01_TargetCarrier -geek-UART  UART 工程
├─ 02_TargetCarrier -geek-I2C   I²C 工程
├─ 03_TargetCarrier -geek-SPI   SPI 工程
└─ 05_上位机                    上位机源码、程序和日志
```

电脑上位机通过设备支持的 BLE 或 GEEK USB 链路访问 X 轴和靶车。使用 GEEK 时，总机可通过 ESP-NOW 与接收端交换数据；接收端与 STM32 的板间链路由对应工程选择 UART、I²C 或 SPI。

## 2 选择通信工程

| 工程 | 作用 | 入口 |
|---|---|---|
| UART | 保存 UART 板间通信工程，以及 X 轴、靶车和 GEEK 源码 | [UART 工程](../01_TargetCarrier%20-geek-UART/) |
| I²C | 保存 I²C 板间通信适配和两端工程，另有靶车 I²C 接线及烧录记录 | [I²C 工程](../02_TargetCarrier%20-geek-I2C/) |
| SPI | 保存 SPI 板间通信适配和两端工程 | [SPI 工程](../03_TargetCarrier%20-geek-SPI/) |

每套工程的 `x轴`、`靶车` 和 `ESP32-S3-GEEK` 分别对应 X 轴控制、靶车控制和 GEEK 总机。I²C、SPI 分支中的 `wired_transport` 保存 ESP32 与 STM32 的板间通信源码、配置和构建适配。

各分支还包含 `tools` 构建及配对脚本、`verification` 验证记录，以及独立的 `portable_comms` TC/2 通信参考工程。TC/2 参考固件的功能范围应查看其自身说明。

## 3 X 轴、靶车与 GEEK

三套通信工程的主要源码结构相近，以相应分支目录为起点。

```text
通信工程
├─ x轴
│  ├─ 野火stm                   X 轴 STM32 工程
│  ├─ esp_无线从机_20261022    X 轴 ESP 无线接收工程
│  ├─ esp                       X 轴另一 ESP 工程
│  ├─ android                   历史 Android 工程
│  └─ 交付文件 / verification   交付与验证资料
├─ 靶车
│  ├─ firmware/stm32_f103       靶车 STM32 工程
│  ├─ firmware/esp32_bridge     靶车 ESP 桥接工程
│  ├─ firmware/esp32_master     靶车 ESP 主机工程
│  ├─ firmware/lib              共用库
│  ├─ docs                      工程说明
│  └─ tools                     构建与测试工具
└─ ESP32-S3-GEEK               GEEK 总机工程
```

UART 分支的 `靶车` 目录还包含手动 360 相关交付。不同分支的文件和配置可能有差异，开发时以所选分支中的源码、配置与交付记录为准。

## 6 验证状态与使用注意

本文只检查了目录、说明文件和部分启动目标是否存在，没有重新编译、烧录、连接设备或运行电机。历史说明中的测试结果只适用于对应版本和当时的测试条件。

11 月 7 日的通信诊断记录包含 BLE 写入超时和控制链路停止现象，具体触发原因当时尚未确认。限位、灯效、速度范围和停止保护可能随分支及固件版本不同而变化。

工程目录经过重命名和整理，部分历史说明、脚本和构建配置可能仍引用旧路径。重新构建或启动前，先核对实际路径、工具链和所选版本。
